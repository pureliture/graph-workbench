# 레퍼런스 정렬 그래프 UX 통합 명세

> 상태: Approved — 사용자가 requirements + design 통합 문서를 승인했습니다.
>
> 문서 유형: requirements + design 통합 문서
>
> 구현 계약: 사용자가 선택한 `agentic-execution`

## 1. 목적

`graph-workbench`의 그래프 화면을 [The AI Coding Dictionary](https://www.aicodingdictionary.com/?term=model-provider-request)의 사용경험과 기능적으로 맞춘다.

캔버스의 색상, 질감, 명암처럼 의도적으로 다른 스타일은 유지할 수 있다. 다만 최대 150개 노드에서 공간 배치, 선택 전환, 관계선 표시, 노드 밀도, 상세 패널의 정보 구조는 레퍼런스와 같은 사용 흐름을 제공해야 한다.

## 2. 확인된 사실

브라우저에서 레퍼런스와 로컬 `/density` 화면을 동일한 viewport에서 선택 상태와 비선택 상태로 각각 확인했다.

- 레퍼런스의 비선택 화면은 연결선을 노출하지 않으면서도 노드와 라벨이 화면 전체에 분산되어 있다.
- 레퍼런스에서 `model-provider-request`를 선택하면 선택 노드는 그래프 영역의 중심 가까이에 남고, 관련 노드와 연결선이 나타나며, 비관계 노드도 낮은 대비로 전체 맥락을 유지한다.
- 레퍼런스의 `model-provider-request` 상세 영역에는 여러 의미 있는 직접 관계, 본문 설명, 보조 행동, 이전·다음 이동이 함께 있다.
- 로컬의 비선택 화면은 노드가 중앙의 작은 군집처럼 보이며 큰 빈 공간이 남는다.
- 로컬의 `relation:query` 선택 화면은 선택 노드와 세 개의 직접 관계만 강조하고, 선택되지 않은 배경 노드와 라벨은 거의 읽히지 않는다.
- 로컬 상세 패널은 테스트용 메타데이터와 세 개의 관계만 제공하고 패널 하단의 빈 공간이 크다.
- 로컬 fixture는 여덟 개의 인공 클러스터, `Density N` 라벨, 세 개의 직접 관계를 사용한다: [DenseGraphFixture.tsx](../sites/browser-fixture/app/density/DenseGraphFixture.tsx#L16), [DenseGraphFixture.tsx](../sites/browser-fixture/app/density/DenseGraphFixture.tsx#L194).
- 로컬은 선택 시 별도 선택 레이아웃과 1-hop 카메라 프레이밍을 적용한다: [layout.ts](../src/layout.ts#L285), [renderer.ts](../src/renderer.ts#L3343).
- 로컬 renderer는 150개 노드에서 body 48개와 label 24개의 표시 예산을 적용하고, 선택되지 않은 노드의 opacity를 별도 단계로 낮춘다: [renderer.ts](../src/renderer.ts#L200), [renderer.ts](../src/renderer.ts#L2170).
- 로컬 density fixture는 `ambientMotion: false`를 설정한다: [DenseGraphFixture.tsx](../sites/browser-fixture/app/density/DenseGraphFixture.tsx#L409).

## 3. 범위와 경계

### 포함

- 최대 150개 노드에서 레퍼런스와 같은 그래프 읽기 흐름
- 비선택, 선택, 선택 해제, 직접 관계 이동의 화면 동작
- 선택 전후의 카메라 프레이밍과 전역 맥락 유지
- 노드·라벨·관계선의 밀도와 강조 계층
- 상세 패널의 정보 구조와 관계 탐색 흐름
- 현재 renderer/layout/browser fixture/test seam의 재사용

### 제외

- 레퍼런스의 흰색 질감 캔버스와 색상 팔레트의 문자 그대로의 복제
- 새로운 store, queue, runtime, public graph contract의 추가
- 배포나 운영 상태를 구현 완료의 증거로 간주하는 것

## 4. 요구사항

### R1. 전역 공간 점유

비선택 상태에서 최대 150개 노드의 표시 subset은 중앙의 작은 군집에 머물지 않고 그래프 viewport 전체에 자연스럽게 분산되어야 한다.

### R2. 선택 시 전역 맥락 유지

노드를 선택해도 선택 노드와 직접 관계만 읽기 쉬워질 뿐, 비관계 노드의 전역 배치가 선택 노드 주변의 인공적인 작은 장면으로 재배치되어서는 안 된다.

### R3. 선택 프레이밍

선택 노드는 상세 패널이 열렸을 때 남은 그래프 영역의 중심 가까이에서 읽혀야 한다. 카메라는 선택 노드와 직접 관계만 과도하게 확대해 배경을 밀어내서는 안 된다.

### R4. 관계선 표시

선택하지 않은 상태에서는 노드 사이의 관계선을 화면에 보이지 않게 한다. 선택 상태에서는 선택 노드에 직접 연결된 관계선만 보이게 한다. 선택되지 않은 배경 관계선은 선택 상태에서도 보이지 않게 한다.

### R5. 배경 맥락과 밀도

선택되지 않은 노드와 라벨은 레퍼런스처럼 낮은 대비로 남아 전체 구조를 이해할 수 있어야 한다. 밀도 제어는 라벨 과밀을 줄여야 하지만, body와 전역 배치를 함께 사라지게 만들어 빈 화면을 만들어서는 안 된다.

### R6. 깊이감

노드의 실제 깊이, 원근에 따른 크기, 명도, 겹침이 함께 작동해 화면이 평면 도식처럼 보이지 않아야 한다. 3D 재질만 바꾸는 것으로 요구사항을 충족한 것으로 간주하지 않는다.

### R7. 관계 데이터의 읽기성

선택된 fixture 노드는 레퍼런스와 유사한 관계 밀도를 검증할 수 있어야 한다. 관계 목록은 `Density N` placeholder만 나열하지 않고, 선택된 노드의 의미 있는 직접 관계를 상세 패널과 캔버스에서 동일하게 제공해야 한다.

### R8. 상세 패널 흐름

상세 패널은 제목, 요약, 직접 관계, 본문 또는 정의, 보조 행동, 이전·다음 이동을 하나의 읽기 흐름으로 제공해야 한다. 패널이 테스트 상태 표시와 빈 공간 중심으로 보이면 안 된다.

### R9. 검증 가능성

각 요구사항은 현재 browser fixture와 Playwright 테스트에서 관찰 가능한 상태로 검증되어야 한다. 단위 테스트 통과만으로 레퍼런스와 같은 사용경험을 주장하지 않는다.

## 5. 제안 디자인

### D1. layout과 camera의 역할 분리

기존 layout의 deterministic base position을 전역 장면의 기준으로 재사용한다. 선택 시에는 선택 노드와 직접 관계의 시각적 강조만 변경하고, 비관계 노드의 위치를 선택 노드 중심으로 재구성하지 않는다.

카메라 전환은 전체 그래프의 전역 프레이밍을 보존하면서 선택 노드를 남은 그래프 영역의 중심으로 부드럽게 가져온다. 1-hop만을 대상으로 한 과도한 `zoomToFit`은 사용하지 않는다.

### D2. renderer-owned visibility tier

관계선의 표시 여부는 기존 selection contract를 재사용한다. body와 label은 선택, 직접 관계, 전역 맥락의 세 단계로 시각적 우선순위를 나누고, 배경 단계에도 읽기 가능한 최소 대비를 둔다.

밀도 culling은 label을 먼저 줄이고 body의 화면 분포는 유지하는 방향으로 적용한다. 표시 예산을 초과하는 경우에도 선택 노드, 직접 관계, 화면 외곽을 포함한 전역 분포가 우선된다.

### D3. 깊이와 움직임

현재 volumetric body와 조명 seam을 재사용한다. z 분포와 원근 스케일이 실제 화면에서 보이도록 base layout과 선택 장면의 깊이 압축을 조정한다. ambient motion은 읽기를 방해하지 않는 범위에서 레퍼런스처럼 정적인 장면이 아닌 깊이 단서를 제공하도록 사용한다.

### D4. 의미 있는 density fixture

최대 150개 규모를 유지하되, 선택 대상과 배경 노드는 의미 있는 라벨과 관계 종류를 갖도록 fixture topology를 조정한다. 선택 대상은 여러 직접 관계를 가져 선택·관계선·상세 패널의 흐름을 검증할 수 있어야 한다.

### D5. 상세 패널과 화면 chrome

기존 drawer의 접근성, history, deep-link, 관계 이동 seam을 유지한다. fixture 전용 `Density renderer ready`와 `Select Query focus` 같은 화면 chrome은 레퍼런스의 실제 탐색 흐름을 가리지 않는 방식으로 재배치하거나 제거한다.

## 6. 관찰 가능한 완료 조건

- 비선택 `/density` 화면에서 관계선은 보이지 않고, 표시된 노드와 라벨은 viewport 전체에 분산된다.
- `relation:query` 또는 동등한 고관계 노드를 선택하면 선택 노드는 그래프 영역 중심 가까이에 위치하고, 직접 관계선만 나타난다.
- 선택 상태에서도 비관계 노드의 위치와 낮은 대비의 맥락이 유지된다.
- 선택 노드의 직접 관계가 캔버스와 상세 패널에서 동일하게 탐색된다.
- 선택 해제 시 전역 장면으로 자연스럽게 복귀하고 관계선이 다시 숨겨진다.
- 상세 패널은 레퍼런스와 같은 정보 순서와 탐색 행동을 제공하며 하단의 비어 있는 공간이 주된 인상이 되지 않는다.
- 최대 150개 fixture에서 label 과밀과 전역 맥락 손실이 동시에 발생하지 않는다.
- 기존 unit, build, rendered-html, browser 검증이 모두 통과하고, 브라우저에서 위 상태를 직접 확인한다.

## 7. 구현 진행 계약

이 작업은 사용자가 명시적으로 선택한 `agentic-execution` 계약으로 진행한다. 문서가 승인되면 구현은 관찰 가능한 end-to-end slice 하나만 활성화하고, 해당 slice의 브라우저 증거를 얻은 뒤 다음 slice로 이동한다.

현재 활성 slice는 없다. 이 문서의 승인이 구현 시작 조건이다.

## 문서 승인 상태

이 통합 문서는 승인되었다. 이 문서의 승인은 구현 계약을 열지만, 배포나 운영 변경을 승인하지 않는다.
